# Showcase edit

The 30-second main film and 14-second cutdown are 1080×1080 H.264 MP4, 30 fps, yuv420p, fast-start. Silent by design for sound-off viewing. No speed changes. Cuts remove preparation/idle time. Visual emphasis comes from large captions, real particle motion and changing display state.

The recordings use the working application's same DOM, handlers, VM and server. A recording-only stylesheet enlarges/rearranges panels and hides unrelated navigation. A cursor ring makes browser interactions visible. This framing does not simulate judgments or replace the display. JUDGE requests in the batch/twist shots use the live API; all numbers in the UI are the responses' original measured wall-clock request latencies. The instruction-set opening is the live instruction explorer; program/end shots use the deterministic 12-instruction teaching cartridge.

Main edit after the visual redesign: 3s instruction-set hook, 6s complete 12-line program, 8s parallel judgments and execution, 8s changed message and response, 5s identity/question. Cutdown selects 3+4+4+3 seconds from those same clips. Both finish on the pixel heart; the opening resolves the headline through the highlighted JUDGE key.

Run `npm start`, then `npm run record`, then `npm run video`. This retains raw WebM recordings, screenshots, per-shot traces, an edit manifest, caption overlays and intermediate clips under `artifacts/raw/` (ignored by Git). Final videos, thumbnail and reproducible scripts are deliverables. Project-local FFmpeg/ffprobe binaries are installed by npm. The caption overlays use system Arial; the UI uses Google Fonts with a sans-serif fallback. New recordings consume API usage and can vary; rerendering existing raw recordings makes no API requests.

The [X creative guidance](https://business.x.com/en/advertising/creative-best-practices) informed immediate motion, short duration and legible sound-off captions. Advertising advice does not guarantee organic performance or sharing. Nothing has been posted to X.
